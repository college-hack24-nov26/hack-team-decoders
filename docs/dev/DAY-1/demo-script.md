# Demo Script — SIH 2026 Live Walkthrough

Target: 8–10 minutes. Covers one full patient journey and one quick physician
view. The seed data provides two additional patients already in the queue so
the dashboard isn't empty.

## Before the demo

```bash
cd infra
docker compose up --build -d        # first time; ~3 min
docker compose run --rm migrate     # apply migrations
docker compose exec backend python -m app.seed_physician
docker compose exec backend python scripts/seed_demo_data.py
```

- Frontend: http://localhost:3000
- Backend Swagger: http://localhost:8000/docs
- No API keys needed — all AI paths fall back to deterministic/local/mock

## Part 1 — The Patient Journey (~6 min)

### 1.1 Language Selection (30 sec)

Open http://localhost:3000. The first screen shows two large buttons.

> "The kiosk greets the patient with a language choice. Large touch targets,
> no reading required — the flag and native script are enough."

Click **हिन्दी** (Hindi). The entire UI switches language.

Switch back to **English** for the demo (or stay in Hindi if your judges read it).

### 1.2 Identity (1 min)

Three tabs: ABHA, Aadhaar, New Patient.

> "A patient arriving with their ABHA number enters it here. We verify it
> against the ABDM gateway."

⚠️ **SAY THIS**: "The ABHA lookup is running against a clearly-labelled mock
provider — there is no ABDM sandbox credential configured. The mock returns
the same data shape a real gateway would, so swapping it in is an interface
change with no caller modifications. The UI shows a DEMO MODE banner."

Enter `91-1234-5678-9012` → Ramesh Kumar auto-populates. Click through.

If judges ask "what if they don't have ABHA?": show the Aadhaar tab or
New Patient form. Point out that Aadhaar is never stored raw (only last 4 +
salted hash).

### 1.3 Consent (1.5 min)

> "Before we touch any data, the patient gives granular consent — section by
> section, each with an audio explanation. This is for a patient who cannot
> read the screen."

Click the speaker icon on each section — the browser TTS reads the explanation
in the selected language. (If TTS doesn't fire on the presenter's laptop, say:
"TTS uses the browser Speech API for the demo; production uses Bhashini.")

Check each section. The submit button stays disabled until both mandatory
scopes are accepted and the audio confirmation box is ticked.

> "No data is collected, no AI call is made, and no screen beyond this is
> reachable until consent is recorded. Revoking consent immediately blocks
> all further processing — we have 12 tests proving this."

### 1.4 Interview (2 min)

> "The adaptive interview uses a deterministic state machine — no LLM, so
> it's predictable, auditable, and fast."

- First question: chief complaint. Choose **Chest Pain**.
- HPI questions appear SOCRATES-style. Answer a few (site: central, onset: hours,
  severity: 9/10).
- When you answer "breathlessness" as an associated symptom → **RED FLAG** fires
  visually mid-interview.

> "That red flag fired from a rules engine, not the LLM — it's immediate,
> deterministic, and testable. The physician sees it before they even look at
> the summary."

Complete the interview or skip remaining optional questions.

### 1.5 Document Upload (30 sec)

> "The patient's old prescriptions and lab reports are photographed here."

Upload a sample image (or just demonstrate the camera button on a real kiosk).
Show the timeline with extracted entities and the red abnormal badge.

## Part 2 — The Physician Dashboard (~2.5 min)

### 2.1 Queue

Log in as physician (Swagger or use the dashboard login if the frontend has it):
- Email: `doctor@medikiosk.in`
- Password: `medikiosk-demo`

> "The queue shows all patients ready for consult. Red-flagged patients sort
> to the top."

Point out Ramesh Kumar is at the top with a red flag indicator.

### 2.2 Summary View

Click into Ramesh Kumar.

> "The structured summary was generated by an LLM constrained to a fixed
> clinical schema — chief complaint, HPI, PMH, drug history, allergies,
> family, personal, ROS, and prior investigations with abnormal flags."

⚠️ **SAY THIS**: "With no LLM API key configured, the summary is assembled
deterministically from the patient's answers — no hallucination possible. If
we set MAIN_LLM_API_KEY, the same endpoint calls GPT-4o-mini with the schema
enforced. The physician always sees it as an editable draft, never a fact."

### 2.3 Confirm & Push

Click Accept. Then "Push to ABDM".

> "A real FHIR R4 document Bundle — Composition, Patient, Condition,
> Observation resources — is generated and POSTed."

⚠️ **SAY THIS**: "The receiver is a clearly-labelled local mock. We generate a
valid FHIR shape so the pipeline is exercised end to end. The response says
'MOCK — accepted N entries, nothing was stored.' Point `ABDM_FHIR_ENDPOINT`
at a real gateway and nothing else changes."

### 2.4 Report Export

Click "Download report" → text file opens (PDF library is a production swap).

## Judges' likely questions — honest answers

| Question | Answer |
|---|---|
| "Is the ABHA check real?" | No. It is a labelled mock returning the same shape a real gateway would. The swap path is one class implementation + one config change. |
| "Does this actually call an LLM?" | Yes if MAIN_LLM_API_KEY is set; otherwise a deterministic fallback rewrites the answers into the summary schema with no model. Both paths produce the same schema. |
| "What about handwriting OCR?" | Printed text only (Tesseract/Google Vision). Handwriting is stubbed with a clear NotImplementedError — it's the biggest technical risk and we're honest about it. |
| "What happens if the patient revokes consent?" | Every endpoint returns 403. We have 12 tests and a Docker verification script proving it. The purge job also deletes raw scans and transcripts. |
| "Is data encrypted at rest?" | Not in this build. PII columns are identified but pgcrypto is not wired. We DO hash Aadhaar, enforce TLS in production config, and purge raw artefacts. |
| "Is this DPDP compliant?" | We implemented: consent before processing, purpose limitation via scopes, data minimisation (Aadhaar hashed, never exported), right to withdraw (instant block), and full auditability. What's missing: column encryption and scheduled retention enforcement. See docs/design/compliance-summary.md. |

---

## What to avoid in the live demo

1. **Don't open multiple patients simultaneously** — the session is per-browser-tab.
2. **Don't type a malformed ABHA** (fewer than 14 digits) then look confused when it fails — that's correct behaviour.
3. **Don't claim the FHIR push reached ABDM** — say "local mock" and show the response.
4. **Don't skip the consent audio** — judges will ask about low-literacy patients.
5. **Don't open the code during the demo** unless a judge asks; reference `docs/design/compliance-summary.md` instead.
